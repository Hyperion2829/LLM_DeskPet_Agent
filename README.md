# 基于 Qwen2.5-7B 与 LoRA 微调的情感感知与动作调度 Live2D 桌面智能体 —— 黍 (Shu)

本项目是一个集成大语言模型（LLM）、三方视觉感知（VLM）与 Live2D 渲染引擎的桌面情感陪伴智能体系统。项目以《明日方舟》干员**“黍（Shu）”**为性格底座，通过监督微调（SFT）使模型具备高度拟真的人设与动作/表情联合调度能力。系统采用本地轻量化推理与前后端解耦的级联架构，支持在消费级显卡（8GB 显存）上流畅运行。

---

## 🏗️ 系统架构设计

为了降低本地物理硬件的负载，系统采用**“解耦级联（Cascading）”**与**“无状态 API 接口”**的架构设计：

```text
  【用户桌面前端】 (Mini Live2D AI.exe, 监听 8000 端口)
        │
        │ 1. 自动截屏 (定周期/事件触发)
        ▼
  【视觉感知模块】 (DashScope Qwen-VL API, 0 显存消耗)
        │
        │ 2. 识别并输出文本描述（例如: "用户正在熬夜码代码"）
        ▼
  【中转控制后台】 (backend.exe, 负责维护短期历史对话记忆)
        │
        │ 3. 组装标准 OpenAI 格式的 messages 历史列表
        ▼
  【本地推理大脑】 (FastAPI 运行在 18080 端口)
        │
        │ 4. 4-bit 实时量化加载 (Qwen2.5-7B-Instruct + 黍 LoRA 补丁)
        │ 5. 格式自动救灾校验
        ▼
  【Live2D 驱动器】 接收 {"text": "...", "action": "..."} 结构化 JSON
        │
        └─► 气泡框显示文本，小人同步播放表情与动作
```

## ✨ 核心特性

1.  **高度拟真的人格对齐**：模型深入学习了“黍”的语气特征（如大姐式的温和碎碎念，常以农耕、四季、时令作比喻），在面临多轮对话或极限越狱测试时，仍能保持极高的人设一致性。
2.  **复合动作表情联合调度**：模型每次对话均直接输出标准的 JSON 代码，同时控制对话文本（`text`）与 Live2D 的 8 类动作表情状态（`action`），建立起情感语境与物理肢体动作的真实映射。
3.  **具身式环境感知能力**：通过级联通义千问视觉大模型，桌宠能隐式“观察”用户的桌面状态，并将其自动转化为自然语言注入上下文，主动发起带有情感温度的日常关怀。
4.  **消费级设备友好（4-bit 量化）**：利用 `bitsandbytes` 库，在加载 14GB 全精度模型的一瞬间，对其进行 **NF4 格式的 4-bit 即时压缩** [1.2.8]，使本地运行显存降低至 **5.5GB 左右** [1.2.8]，在 8G 显卡上可顺畅运行。

## 🚀 快速开始与使用指南

本项目为不同需求的使用者提供两条部署路径。**如果你只是想快速体验或进行答辩演示，推荐使用【路径 A】。**

---

### 【路径 A】极速体验（推荐 🌟，无需配置 Python 环境，0 显存，调用云端）

*适合只想运行桌宠进行体验、或者评审老师快速验收。该路径下，模型大脑运行在云端 API（如官方 DeepSeek），无需本地显卡。*

1. **一键下载**：前往本仓库的 [Releases](https://github.com/Hyperion2829/LLM_DeskPet_Agent/releases) 页面，下载 **`Mini_Live2D_AI_v1.0.0.zip`** 并解压。
2. **配置 Key**：在解压出的文件夹中，将 `.env.template` 复制一份改名为 `.env`，填入你真实的 `DEEPSEEK_API_KEY`（如需视觉，再填入 `DASHSCOPE_API_KEY`） [2]。
3. **启动**：双击运行 **`Mini Live2D AI.exe`**，即可直接开始在桌面与黍对话 [1.1.6]！
*(注：此路径不需要 git clone 本仓库，也无需配置任何 Python 环境)*。

---

### 【路径 B】源码部署与二次开发（本地 8G 显存运行，调用本地大模型）

*适合开发者、助教进行源码审核与复现。大模型大脑完全运行在本地显卡上。*

#### 1. 克隆代码仓库
```bash
git clone https://github.com/Hyperion2829/LLM_DeskPet_Agent.git
cd LLM_DeskPet_Agent
```
*(此时你本地拥有了完整的训练、评测源码，以及前端的 JS/HTML 源码，但 `Shu_live2D` 目录下缺少编译好的 `.exe` 启动程序。)*

#### 2. 补齐本地可执行程序 (Binaries)
1. 前往本仓库的 [Releases](https://github.com/Hyperion2829/LLM_DeskPet_Agent/releases) 页面。
2. 下载 **`Mini_Live2D_AI_v1.0.0.zip`** 并解压。
3. **关键操作**：将解压出来的 `Mini Live2D AI.exe`、`backend.exe` 及其所有的 `.dll` 动态链接库文件，**直接复制并粘贴到你刚刚 clone 下来的 `Shu_live2D/` 文件夹下**。
*(这样，你克隆的代码仓库与可执行程序就完美融为了一体，没有产生任何多余的重复文件夹)*。

#### 3. 配置本地 Python 运行环境
在项目根目录下打开 **Anaconda Prompt**，依次运行：
```cmd
# 一键配置依赖环境 (conda 环境名为 pet_local)
setup_local\setup_local.bat

# 一键下载 14G Qwen2.5 官方底座
python setup_local/download_local.py
```

#### 4. 导入 LoRA 补丁（黍之灵魂）
1. 从 Releases 页面下载你打包好的微调补丁 **`shu_lora_adapter.zip`**。
2. 解压并将其中的 `shu_lora` 文件夹放置到本地 `models/checkpoints/` 目录下。

#### 5. 双击一键启动
1. 双击运行项目根目录下的 **`run_local.bat`**（在 18080 端口载入 4-bit 模型并提供服务） [1.1.4, 1.2.8]。
2. 配置好 `Shu_live2D/.env` 文件（指向本地 `18080` 端口） [1.1.2]。
3. 双击运行 `Shu_live2D/Mini Live2D AI.exe` [1.1.6]。
```

## 🚀 启动与前后端联调

### 1. 启动大模型推理后端 (18080 端口)
在本地项目根目录下，**直接双击运行：`run_local.bat`**。
*   该脚本会自动调用本地 `pet_local` 环境下的 Python 解释器 [1.1.4, 2]，以 **4-bit 实时量化** 形式载入 Qwen2.5-7B 底座并贴上 LoRA 补丁 [1.2.8]。
*   当黑窗口输出 `✅ 极简本地推理服务已就绪！` 时，代表服务已成功挂载在 `127.0.0.1:18080` [1.1.4]。

### 2. 启动 Live2D 桌面端前端 (8000 端口)
1.  将安装目录下的 `.env.template` 复制一份，改名为 `.env`, 用文本编辑器打开 `Shu_live2D/.env`，修改并保存为以下内容 [1.1.2]：
    ```ini
    DEEPSEEK_API_KEY=sk-any-fake-key-here
    DEEPSEEK_BASE_URL=http://127.0.0.1:18080/v1
    
    # ⚠️ 如需启用视觉感知，请在此处填写申请好的真实的阿里云 DashScope Key
    DASHSCOPE_API_KEY=sk-你的真实阿里Key
    ```
2.  用文本编辑器打开 `Shu_live2D/config.json`，确保里面的 `"vision.enabled"` 设为了 **`true`**（如不使用视觉则保持为 `false`） [2]。
3.  **直接双击运行：`Shu_live2D/Mini Live2D AI.exe`** [1.1.6]。

现在，你直接在桌宠底部的输入框打字发送（或开启视觉自动截屏），大模型后台终端便会开始滚动计算，Live2D 小人也会生动地说话并动起来 [1.1.2]！

## 📊 评测体系与对比实验结果

根据课程要求，本项目使用 1000 条严格的离线测试集（涵盖日常对话、安全防越狱、多类情绪动作分类和视觉感知），分别对 Qwen2.5 基座模型与微调后的 LoRA 模型进行了自动量化评估，评测数据对比如下：

### 1. 指标数据对比表
| 评测指标 | 基座模型 (Base-7B-Instruct) | 微调模型 (LoRA-4k-SFT) | 性能增益 (Delta) |
| :--- | :---: | :---: | :---: |
| **整体样例通过率** | 16.60% | **57.10%** | **+40.50%** |
| **平均规则通过率** | 78.88% | **89.15%** | **+10.27%** |
| **平均人格得分 (Judge)** | 3.62 / 5.00 | **4.43 / 5.00** | **+0.81** |
| **JSON 结构合法率** | 99.50% | **99.80%** | +0.30% |
| **动作 (Action) 语境匹配率** | 17.20% | **57.10%** | **+39.90%** |
| **长度合规率** | 98.60% | **99.80%** | +1.20% |
| **禁用表达规避率** | 99.60% | **100.00%** | +0.40% |
| **仅输出 JSON 约束率** | 99.50% | **99.80%** | +0.30% |

### 2. 评测结论分析
*   **动作匹配的绝对跨越**：基座模型（Base）虽具有极好的 JSON 遵循度，但完全不具备“黍”特定动作的调度常识，产生了大面积的动作失配。而微调模型将**动作匹配率提升了近 $40\%$**，证明了多任务 SFT 建立了稳固的语境-动作分类关系。
*   **灵魂人设的深度对齐**：通过 LLM-as-a-Judge 的客观打分，LoRA 模型在人设分上取得了 **4.43 分** 的优秀表现。模型彻底规避了“作为一个AI助手”等机械表达，能以极具温度的陪伴交互。
