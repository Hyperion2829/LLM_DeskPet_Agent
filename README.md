# 基于 Qwen2.5-7B 与 LoRA 微调的情感感知与动作调度 Live2D 桌面智能体 —— 黍 (Shu)

本项目实现了一个面向桌面交互场景的情感陪伴智能体系统，集成大语言模型（LLM）、第三方视觉语言模型（VLM）与 Live2D 渲染引擎。项目以《明日方舟》干员 **“黍（Shu）”** 为角色设定基础，通过监督微调（SFT）增强模型在人格一致性、对话风格保持以及动作调度方面的能力。项目采用本地轻量化推理与前后端解耦的级联架构，支持在消费级显卡（8GB 显存）上运行。


## 系统架构

为降低本地物理硬件负载，系统采用**模块化拆分**与**轻量化无状态 API 接口** 的设计。视觉感知由 DashScope Qwen-VL API 提供，本地推理服务通过 FastAPI 加载 Qwen2.5-7B-Instruct 与黍 LoRA 补丁，前端根据结构化 JSON 输出文本并驱动 Live2D 动作。

```text
  【用户桌面前端】 (Mini Live2D AI.exe, 监听 8000 端口)
        │
        │ 1. 自动截屏 (定周期/事件触发)
        ▼
  【视觉感知模块】 (DashScope Qwen-VL API)
        │
        │ 2. 识别并输出文本描述（例如: "用户正在熬夜码代码"）
        ▼
  【中转控制后台】 (backend.exe, 负责维护短期历史对话记忆)
        │
        │ 3. 组装标准 OpenAI 格式的 messages 历史列表
        ▼
  【本地推理大脑】 (FastAPI 运行在 18080 端口)
        │
        │ 4. 4-bit 实时量化加载 (Qwen2.5-7B-Instruct + 黍 LoRA 补丁)
        │ 5. 格式自动校验与容错修复
        ▼
  【Live2D 驱动器】 接收 {"text": "...", "action": "..."} 结构化 JSON
        │
        └─► 气泡框显示文本，live2d 模型播放动作
```


## 核心特性

1. **人格一致性对齐**

   模型学习了“黍”的语气特征，包括大姐式的温和叙述习惯，以农耕、四季、时令作为比喻的表达方式。在多轮对话和极限越狱测试场景下，模型仍能够保持较高的人设一致性。

2. **动作调度**

   模型在每轮对话中直接输出标准 JSON 结构，同时控制对话文本（`text`）与 Live2D 的 8 类动作表情状态（`action`），建立情感语境与物理肢体动作之间的映射关系。

3. **环境感知能力**

   系统通过通义千问视觉大模型，使桌宠能够基于用户当前屏幕状态生成文本描述，并将该描述自动注入对话上下文，从而支持主动、自然的日常关怀式交互。

4. **消费级设备可部署性**

   系统使用 `bitsandbytes` 库，在加载 14GB 全精度模型时执行 **NF4 格式的 4-bit 即时压缩**，将本地运行显存占用降低至 **约 5.5GB**，可在 8GB 显存显卡上运行。

## 快速开始

本项目提供两种部署路径。路径 A 适用于快速体验，无需本地部署，直接调用第三方 api，不使用微调模型；如需体验完整微调模型效果，请使用路径 B。本项目目前只包含 Windows 便携版，无需安装。


### 路径 A：快速体验（无需配置环境，调用云端 API）

该路径适用于桌宠体验、演示和快速验收。模型推理由云端 API 提供，无需本地显卡资源，不使用微调模型。

1. **下载发布包**：前往本仓库的 [Releases](https://github.com/Hyperion2829/LLM_DeskPet_Agent/releases) 页面，下载 **`Mini_Live2D_AI_v1.0.0.zip`** 并解压。

2. **配置 API Key**：在解压后的目录中，将 `.env.template` 复制并重命名为 `.env`，填入真实的 `DEEPSEEK_API_KEY`。如需启用视觉感知功能，同时填入 `DASHSCOPE_API_KEY`（支持使用任何兼容 OpenAI 接口的第三方 API，但需更改 `config.json` 中的模型名称）。

3. **启动客户端**：双击运行 **`Mini Live2D AI.exe`**，即可在桌面端与黍进行对话。

> 该路径不需要 `git clone` 本仓库，也不需要配置 Python 环境。


### 路径 B：源码部署与二次开发（本地 8GB 显存运行，调用本地大模型）

该路径使用微调模型，模型推理完全在本地显卡上运行。

#### 1. 克隆代码仓库

```bash
git clone https://github.com/Hyperion2829/LLM_DeskPet_Agent.git
cd LLM_DeskPet_Agent
```

克隆完成后，本地将包含完整的训练、评测源码以及前端 JS/HTML 源码；但 `Shu_live2D` 目录下尚未包含打包后的 `.exe` 启动程序。

#### 2. 补齐本地可执行文件

1. 前往本仓库的 [Releases](https://github.com/Hyperion2829/LLM_DeskPet_Agent/releases) 页面。
2. 下载 **`Mini_Live2D_AI_v1.0.0.zip`** 并解压。
3. 将解压得到的 `Mini Live2D AI.exe`、`backend.exe` 及全部 `.dll` 动态链接库文件，复制到本地仓库的 `Shu_live2D/` 目录下。


#### 3. 配置本地 Python 运行环境

在项目根目录下打开 **Anaconda Prompt**，依次执行：

```cmd
# 一键配置依赖环境（conda 环境名为 pet_local）
setup_local\setup_local.bat

# 一键下载 14GB Qwen2.5 官方底座
python setup_local/download_local.py
```

#### 4. 导入 LoRA 补丁

1. 从 Releases 页面下载已打包的微调补丁 **`shu_lora_adapter.zip`**。
2. 解压后，将其中的 `shu_lora` 文件夹放置到本地 `models/checkpoints/` 目录下。

#### 5. 启动本地服务与前端

1. 双击运行项目根目录下的 **`run_local.bat`**（在 18080 端口加载 4-bit 模型并提供服务）。
2. 配置 `Shu_live2D/.env` 文件，使前端请求指向本地 `18080` 端口。
3. 双击运行 `Shu_live2D/Mini Live2D AI.exe`。


## 启动与前后端联调

### 1. 启动大模型推理后端（18080 端口）

在本地项目根目录下，双击运行`run_local.bat`。

该脚本会自动调用本地 `pet_local` 环境下的 Python 解释器，并以 **4-bit 实时量化** 形式加载 Qwen2.5-7B 底座与 LoRA 补丁。

当终端输出以下内容时，表示服务已成功挂载在 `127.0.0.1:18080`：

```text
✅ 极简本地推理服务已就绪！
```

### 2. 启动 Live2D 桌面端前端（8000 端口）

1. 将安装目录下的 `.env.template` 复制并重命名为 `.env`。随后使用文本编辑器打开 `Shu_live2D/.env`，将其修改并保存为以下内容：

   ```ini
   DEEPSEEK_API_KEY=sk-any-fake-key-here
   DEEPSEEK_BASE_URL=http://127.0.0.1:18080/v1
   
   # 如需启用视觉感知，请在此处填写申请好的真实阿里云 DashScope Key
   DASHSCOPE_API_KEY=sk-你的真实阿里Key
   ```

2. 使用文本编辑器打开 `Shu_live2D/config.json`，确认其中的 `"vision.enabled"` 已设置为 **`true`**。如不使用视觉感知，则保持为 `false`。

3. 双击运行 `Shu_live2D/Mini Live2D AI.exe`。

完成上述步骤后，可在桌宠底部输入框发送文本；如启用视觉感知，也可由系统自动截屏并生成上下文描述。大模型后端将开始计算，Live2D 前端将同步显示文本气泡并播放对应动作。

## 评测体系与对比实验结果

根据课程要求，本项目构建了 1000 条离线测试集，覆盖日常对话、安全防越狱、多类情绪动作分类和视觉感知场景。评测分别针对 Qwen2.5 基座模型与微调后的 LoRA 模型进行，自动量化评估结果如下。

### 指标数据对比

| 评测指标 | 基座模型 (Base-7B-Instruct) | 微调模型 (LoRA-4k-SFT) | 性能增益 (Delta) |
| :--- | :---: | :---: | :---: |
| **整体样例通过率** | 16.60% | **57.10%** | **+40.50%** |
| **平均规则通过率** | 78.88% | **89.15%** | **+10.27%** |
| **平均人格得分 (Judge)** | 3.62 / 5.00 | **4.43 / 5.00** | **+0.81** |
| **JSON 结构合法率** | 99.50% | **99.80%** | +0.30% |
| **动作 (Action) 语境匹配率** | 17.20% | **57.10%** | **+39.90%** |
| **长度合规率** | 98.60% | **99.80%** | +1.20% |
| **禁用表达规避率** | 99.60% | **100.00%** | +0.40% |
| **仅输出 JSON 约束率** | 99.50% | **99.80%** | +0.30% |

### 评测结论

- **动作匹配能力显著提升**：基座模型（Base）具备较高的 JSON 格式遵循能力，但缺少针对“黍”角色动作体系的调度知识，导致动作语义匹配不足。微调模型将动作匹配率提升近 **40%**，表明多任务 SFT 有效建立了语境与动作分类之间的映射关系。
- **角色人格对齐效果稳定**：基于 LLM-as-a-Judge 的评测结果显示，LoRA 模型在人格得分上达到 **4.43 / 5.00**。模型能够规避“作为一个 AI 助手”等机械化表达，并以符合角色设定的方式完成陪伴式交互。
